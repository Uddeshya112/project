# Sample data and demo accounts

The sample data is kept on purpose so the app is usable straight after install. It is ordinary data: coordinators can edit, replace (Excel import in `replace` mode) or delete it, and admins can change or remove the accounts.

> **Before real use:** set `DEMO_MODE=false` and change or lock the seven sample accounts. With demo mode on, anyone who opens the sign-in page can act as the demo College Admin: edit data, publish timetables and manage users. With demo mode off the five demo accounts are refused entirely (buttons, password sign-in and existing sessions).

## When it is loaded

Only on first start with an empty database:

- `SEED_DEMO_DATA` (default `true`): academic dataset and baseline timetable, when there is no academic data yet.
- `SEED_SAMPLE_USERS` (default `true`; only `false` disables it): the 12 accounts below, when the users table is empty.

Later restarts never overwrite existing data or passwords.

## Dataset `TIET-STRESS-1000-500-V1`

Generated deterministically by `src/server/demoData.ts`:

- 5 departments (CSED, ECED, MED, CED, EED) and 5 B.Tech programs
- 500 faculty (`fac-0001` is Prof. Arvind Sharma, `arvind.sharma@thapar.edu`; the rest use `faculty.fac-NNNN@thapar.edu`)
- 80 rooms: 38 lecture halls, 12 seminar rooms, 20 computer labs, 10 hardware labs
- 32 groups (CSE-A, CSE-B, ...), each with 2 subgroups of 20; 1,280 students
- 80 courses and 288 course allocations
- a baseline timetable generated by the engine (`FAST`, seed 1337) and published as version 1, plus sample notifications and audit entries

## One-click demo sign-in

With `DEMO_MODE=true` (default) the sign-in page shows buttons for Coordinator, Faculty, Student, Admin and HOD. Each signs in as the matching demo account through `POST /api/auth/demo-login`, with a normal session. With `DEMO_MODE=false` the buttons are hidden and that endpoint returns 403.

Demo accounts cannot use Google sign-in. There is no reset endpoint for sample data; to start over, see "Useful SQL" in [DATABASE_ARCHITECTURE.md](DATABASE_ARCHITECTURE.md).

## Turning it off

For a new production database:

```
DEMO_MODE=false
SEED_DEMO_DATA=false
SEED_SAMPLE_USERS=false
BOOTSTRAP_ADMIN_EMAIL=you@thapar.edu
```

Without sample data the Google roster is empty, so only the bootstrap admin can sign in until faculty and students are imported (or accounts are created in Admin -> Users & Roles).

For a database that already has the sample accounts: set `DEMO_MODE=false` (demo accounts are then refused) and change or lock the sample accounts.
